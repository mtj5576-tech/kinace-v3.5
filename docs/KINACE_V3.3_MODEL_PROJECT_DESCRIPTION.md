# Kinace V3.3 模型项目说明（公开版）

> 文档版本：3.3.0  
> 更新日期：2026-09-20  
> 适用范围：项目介绍、合作沟通、技术交流和外部评审  
> 披露原则：本文说明系统能力、算法类型和验证框架，不披露权重、阈值、因子公式、核心代码结构、参数寻优细节和可直接复现模型的实现方案。

## 1. 项目概述

Kinace V3.3 是一套面向中国 A 股市场的本地量化研究与每日策略系统。系统覆盖市场数据维护、研究快照、候选评估、组合回测、稳定性复核、运行审计、每日策略生成和只读看板。

当前模型不是深度学习或大规模神经网络系统，而是以规则化多因子评分、统计校准、时间序列验证和回测驱动参数优化为核心的量化策略模型。

系统当前定位为研究与每日策略参考平台，不连接券商账户，不自动执行实盘订单，也不自动替换生产模型。

## 2. 系统目标

Kinace V3.3 主要解决五类问题：

1. 持续维护全市场行情和研究数据。
2. 在每个交易日形成一致的决策日快照。
3. 对候选策略进行组合级回测和风险分析。
4. 对研究结果执行独立审计、稳定性复核和资格检查。
5. 通过本地看板输出每日策略、交易计划和历史日报。

系统强调可追溯、可复算、可审计和失败关闭，而不是追求未经验证的高收益结果。

## 3. 模型类型与算法范围

### 3.1 多因子线性评分

当前模型以多因子加权评分作为核心排序方法。模型将不同维度的市场信息标准化后组合为候选分数，并按照分数对股票进行排序。

公开层面可以说明的因子类别包括：

- 趋势与动量。
- 价格位置。
- 成交量与流动性。
- 成交金额与市场活跃度。
- 相对行业或市场强弱。
- 短期跳空和波动特征。

### 3.2 横截面标准化

不同股票的市场量纲和分布差异较大，因此系统使用带 MAD 去极值的横截面标准化方法，将同一决策日内的候选转换为可比较的相对分数。

标准化的分位处理、异常值阈值、可选中性化方式和最终变换细节不公开。

### 3.3 非线性惩罚与风险修正

基础评分之外，系统会对特定高风险状态进行额外修正，例如过热、异常波动或风险收益结构不匹配。

惩罚条件、触发阈值、分段函数和修正上限属于核心设计，不在本文公开。

### 3.4 排序信息系数校准

在部分研究阶段，系统使用排序信息系数（Rank IC）、ICIR 和符号稳定性对因子权重进行统计拟合。负向预测信息通过方向翻转保留，而不是简单归零。

模型不会将预测值当作真实标签，也不会使用未来数据反向校准历史决策日。

### 3.5 确定性参数搜索

系统使用确定性网格展开和邻域探索构建候选参数组合。该方法适合重复实验、结果复算和审计，不依赖不可复现的随机搜索结果。

### 3.6 单主目标与约束评分

阶段 3 起，参数候选以一个风险调整后的净值 Sharpe 作为单一排序目标。收益、回撤、换手、Profit Factor 和胜率不再作为重复加权的奖励项，而是作为候选资格约束。

公开可说明的约束维度包括：

- 最小交易数量。
- 最大回撤。
- 每个交易日的组合换手。
- 最低 Profit Factor。
- 最低总收益和胜率。

特征权重集中度在阶段 4 已转为绑定约束，并通过约束投影在求解阶段直接满足。

## 4. 验证算法框架

### 4.1 时间序列 Walk-Forward 验证

系统采用滚动时间序列验证，而不是随机打乱训练集和验证集。这样可以保留市场数据的时间顺序，降低前视偏差。

验证框架包含训练、验证、测试、清洗和禁入区间。

### 4.2 固定 Holdout

候选策略只有在训练和滚动验证阶段通过后，才允许进入固定留出集复核。Holdout 用于检查候选是否只在训练窗口内有效。

### 4.3 连续组合回测

系统不是对单只股票独立测算收益，而是使用单一资金账户进行连续组合模拟，统一处理现金、持仓、建仓、退出、手续费、滑点、停牌和涨跌停约束。

该设计用于减少“每只股票独立满仓”造成的收益虚高。

### 4.4 波动率风险控制

组合执行层使用平均真实波幅（ATR）构建自适应止损和止盈参考线，并设置最长持有期限。当前每日策略会输出参考价、ATR、计划止损和计划止盈。

次日实际开盘后，最终交易线会按照实际入场价重新计算，避免把决策日收盘价误当成真实成交价。

具体 ATR 周期、风险倍率和持有期限不在本文公开。

### 4.5 稳定性复核

通过初步回测的候选还会进入稳定性复核，包括：

- 基于 8 个 walk-forward 窗口的配对差值 bootstrap 置信区间检查。
- 交易成本与滑点压力分布检查。
- 市场过滤条件响应面检查。
- 特征权重集中度检查。
- 候选与基线在相同窗口和快照集上的比较。

Holdout 不混入滚动稳定性窗口，只用于最终留出集判决。稳定性复核未通过的候选不会进入后续晋级阶段。

## 5. 数据治理算法

### 5.1 多源行情校验

系统对重叠日期的行情执行跨源一致性检查，包括收益、开高低收关系和成交量口径。检查未通过时，增量数据不会写入 canonical 数据层。

### 5.2 价格连续性检查

系统检查极端的单日价格跳变、跨源价格断点和异常 OHLC 数据。发现问题时形成审计证据，而不是静默修补。

### 5.3 Point-in-Time 股票池

历史研究按照决策日构建 point-in-time 股票池，避免仅使用当前仍存在的股票回填历史。未经确认的历史成分和未经验证的数据不会被当作有效训练样本。

### 5.4 不可变数据版本

行情修订采用追加式记录和稳定标识。历史记录不会被静默覆盖，更新以新版本和血缘关系表达。

### 5.5 数据与执行审计

审计范围包括价格连续性、跨源一致性、停牌与涨跌停状态、执行重放、费用、滑点和历史股票池完整性。严重问题会阻止后续研究或发布。

## 6. 资格门与治理

系统将研究治理拆分为多类资格门，包括证据绑定、候选专属回测、完整 PIT 股票池、执行审计、稳定性复核和无人值守运行观察。

当前状态：

- 数据与执行审计：通过。
- 完整 PIT 股票池：通过。
- 候选证据绑定和候选级 release gate：已通过过。
- 策略稳定性：仍存在 `review_required`。
- 无人值守观察：尚未完成 20 个交易日。
- 自动生产晋级：关闭。

因此，当前模型可以产生每日策略和研究结论，但不能被视为已经达到生产自动晋级标准。

## 7. 每日策略输出

每日策略 artifact 当前包含：

- 策略候选和排名。
- 原始分数、调整分和扣分项。
- 决策日参考价。
- ATR 风险指标。
- 计划止损与计划止盈。
- 止损和止盈相对参考价的百分比。
- 评分来源、回放、快照和候选血缘。

看板提供按决策日切换的历史策略入口，并可从每个历史策略直接打开对应的人工审阅日报。

## 8. 工程与运行能力

Kinace V3.3 当前具备：

- 全市场每日数据更新。
- 自动快照和 gate 检查。
- 每日策略生成。
- 连续组合回测。
- 研究候选生成、验证和稳定性复核。
- Windows Task Scheduler 自动运行。
- SQLite 运行台账和自动备份。
- 本地只读看板。
- EXE 一键启动。
- 历史策略和日报审阅入口。
- 失败日志、告警和状态门禁。

## 9. 当前限制

- 系统不连接实盘券商，不下单，不管理真实资金。
- 当前不自动修改或晋级生产模型。
- 今日盈亏和今日盈亏比属于模拟组合口径。
- 执行模拟尚未覆盖完整订单簿、冲击成本和所有交易所特有规则。
- 策略稳定性尚未整体通过。
- 20 个交易日无人值守观察尚未完成。
- Shadow trading、人工审批、原子替换和自动回滚尚未启用。

## 11. 总结

Kinace V3.3 当前是一套具备全市场数据维护、量化回测、研究验证、风险控制和每日策略输出的本地研究系统。它已经形成可追踪、可审计和可复算的工程闭环。

当前最重要的剩余工作不是增加模型复杂度，而是完成策略稳定性复核和 20 个交易日的无人值守验收。在这两项完成前，系统不应进入自动生产晋级阶段。
