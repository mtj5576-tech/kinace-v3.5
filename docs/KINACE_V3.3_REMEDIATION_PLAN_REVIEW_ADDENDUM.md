### 1.3 两处需要重新表述的结论

#### 1.3.1 `R_total` 与 `R_ann` 的关系

**原审查表述（错误）**：

```
R_total <-> R_ann 相关系数恒为 1.00
```

**实际关系**（复核数据）：

| periods | Pearson | Spearman |
|---|---|---|
| 20 | 0.3773 | 1.0000 |
| 60 | 0.8949 | 1.0000 |
| 120 | 0.9837 | 1.0000 |
| 250 | 1.0000 | 1.0000 |
| 1000 | 0.9882 | 1.0000 |

`R_ann = (1 + R_total)^(252/periods) - 1` 是 `R_total` 的**确定性单调变换**：

- **Spearman 恒为 1** —— 排名完全相同，不携带任何新的排序信息
- **Pearson 不恒为 1** —— 随窗口变短而下降（变换的凸性增强）

**进一步复核：`R_ann` 项是否改变 J 的最优候选？**

在 2000 个合成候选上测试，去掉 `R_ann` 项后 **J 的 argmax 索引完全未变**。原因是 `clamp(R_ann, -2, 2)` 在高收益候选上饱和为常数 `2.0`，无法区分它们。

**因此准确的表述是**：

```
R_ann 项既不携带排名信息 (Spearman=1)，
其 0.25 权重在短窗口下又被 clamp 大量吃掉，
是一个"看起来有意义、实际作用很小"的项。
```

这比"共线重复计分"更强也更弱——不是重复，而是**基本不工作**。

**对计划的含义**：§5（阶段 3）提出的"单主目标 + 硬约束"改写是对的，且比原审查建议的更必要。

#### 1.3.2 Logistic 映射

**撤回"空操作"判断。** 存在 `min_score` 阈值时，`p > min_score` 等价于对调整分数 `A` 设置隐式阈值。

补充观察：若 `min_score = 0.5`，则隐含阈值是 `A = 0`。而 `S = sum_f w'_f * z_{i,f,t}` 是权重和为 1 的横截面 z-score 加权和，所以：

```
A = 0  <=>  综合分等于截面均值
```

这个含义本身是合理的，但它是**隐式**的。建议在阶段 0 的 manifest 中显式记录：

```text
min_score
=> 隐式调整分数阈值 = logit(min_score)
=> 语义 = 相对截面均值的位置
```

## 2. 对计划的细化建议 R1–R9

### R1 · 阶段 1 的候选级判决应标注为"临时"

**位置**：计划 §3（阶段 1）

**问题**：阶段 1 与阶段 2 存在耦合。

```text
阶段 1 建立统计判决 -> 依赖当前 OOS 收益序列
阶段 2 修改标签定义 -> OOS 收益序列改变
                    -> 阶段 1 对候选的判决被作废
```

阶段 1 的**统计机器**（bootstrap、DSR、`N_eff`）是可复用的工具；但阶段 1 的**候选级结论**会在阶段 2 之后失效。

**建议**：拆分为两个子阶段，并在文档中明确标注。

```text
阶段 1a  建立统计判决机器 (bootstrap / DSR / N_eff / N_trials 记账)
         -> 可复用, 不依赖标签定义

阶段 1b  对当前候选出判决
         -> 标注为 provisional, 阶段 2 完成后必须重跑
```

**验收条件**：

```text
阶段 1a 的工具在阶段 2 之后无需修改即可复用
阶段 1b 的输出明确标注 "provisional, 待阶段 2 后重跑"
阶段 7 重跑时不出现 "阶段 1 结论与阶段 7 结论矛盾但无法解释" 的情况
```

### R2 · `N_trials` 的口径严重不完整 ⚠️ 高优先级

**位置**：计划 §3（阶段 1）第 5 项

**问题**：计划列出的 `N_trials` 来源为：

```text
+ 本次 loop 候选数
+ 历史 weekly / 研究 loop 候选数
+ 成本敏感性试验数
+ 市场过滤敏感性试验数
```

**遗漏的来源**：

| 遗漏项 | 说明 |
|---|---|
| `ModelSpace` 网格 | 权重组合的搜索空间 |
| `BacktestSpace` 网格 | ATR 参数、最长持有期、持仓数量、`min_score` 等 |
| 股票池与过滤阈值选择 | §3.2 提到的 `RSI_limit`、`KDJ_limit`、`p_overheat`、`theta_amp`、`lambda_amp` |
| 特征工程选择 | 8 个因子的取舍、标准化方式 |
| **历史上跑过的每一次回测** | 最关键，包含"试了一下觉得不行就扔掉"的那些 |

**为什么这条是决定性的**：

DSR 的零假设基准为 `SR_0 ≈ sqrt(2 * ln(N)) / sqrt(T)`。**该式对 `N` 是对数敏感的**——少算一个数量级，`SR_0` 就系统性偏小，DSR 随之失真，最优候选的显著性被高估。

**建议**：

1. 给**每一次回测**打一个 `config_hash` 并落库，无论结果好坏。
2. `N_trials` = 去重后的 `config_hash` 数量。
3. 该计数必须能被 D1 反查（进入 `replay_bound`）。
4. 单独报告"历史上被丢弃的候选数"，因为这是最容易被少算的部分。

**验收条件**：

```text
每一次回测都有 config_hash 记录, 包含失败和放弃的
N_trials 可从证据链反查, 而不是人工估计
报告 N_trials 时同时给出历史累计值和本次 loop 值
```

**预期**：这个数会显著大于计划当前的估计。这是正常的，也是必要的。

### R3 · 阶段 5 的置信区间突破不了样本量上限 ⚠️ 高优先级

**位置**：计划 §7（阶段 5）

**问题**：计划把稳定性门禁从"小样本比例"改为"置信区间"——**方向完全正确**。但需要明确一点：

```text
bootstrap 给出的是诚实但可能永远通不过的区间
它不创造信息, 只如实反映样本量的限制
```

如果窗口数只有 4 个，即使改用 bootstrap，置信区间仍会宽到**必然包含 `-epsilon`**。这会导致门禁**恒失败**——不是候选不行，是设计问题。

**建议**：增加窗口数量。这是一处成本很低的设计改动。

| `validation_sessions` | 可得窗口数（近似） | 说明 |
|---|---|---|
| 40（当前） | 3–4 | 置信区间过宽 |
| **20** | **8–10** | 推荐起点 |
| 15 | 11–13 | 进一步增加，但单窗口变短 |

**注意权衡**：`validation_sessions` 减小会让每个窗口的估计更噪声。建议做法是——**先用 20 试跑，观察置信区间宽度是否下降到有判别力的水平**，再决定是否继续减小。

**另一个必须明确的点**：计划的 `window_count = 4` 包含"3 个 fold + 最终 Holdout"。**把 Holdout 混入滚动稳定性统计在概念上是有问题的**——Holdout 是最终判决，不是滚动窗口，它的分布特性和 fold 不同（它是最后一段，且被用于最终决策）。

建议：

```text
滚动稳定性统计: 只用 walk-forward fold
Holdout: 单独作为最终判决, 不参与 q_noninferior 的计算
```

否则 `window_count = 4` 会把一个性质不同的窗口混进比例里。

**验收条件**：

```text
稳定性门禁的置信区间宽度足以区分 "有真实差异" 和 "无差异"
若候选显著优于 baseline, 门禁能够通过 (即门禁不是恒失败)
滚动稳定性只使用 walk-forward fold, Holdout 单独判决
```

### R4 · 阶段 3 的权重硬约束与阶段 4 的求解器耦合

**位置**：计划 §5（阶段 3）与 §6（阶段 4）

**问题**：阶段 3 把下列指标改为硬约束：

```text
max_feature_weight <= weight_budget
```

但让该约束**可满足**的是阶段 4 的投影求解器。在阶段 4 之前：

```text
IC^+ 结构 -> 学习权重必然趋近 one-hot
          -> 网格中绝大多数点违反 max_feature_weight
          -> 可行集可能为空
```

**建议**：分两步落地。

```text
阶段 3: 把 max_feature_weight 作为"报告项"
        - 记录每个候选的实际 max_weight
        - 不参与可行性判断
        - 用于量化约束的紧张程度

阶段 4: 投影求解器就位后, 转为"绑定约束"
        - w = ProjectOntoConstrainedSimplex(w_raw, max_weight)
        - 此时可行集非空
```

**顺带明确**：`max_weight` 的检查时机。计划 §6.3 要求"最终权重在收缩之后仍满足 max_weight 约束"——这是对的，因为 §5.3 还有一步 `0.75 * w_learned + 0.25 * w_base` 的收缩。投影必须在收缩**之后**校验，或直接对收缩后的结果做投影。

**验收条件**：

```text
阶段 3 结束时能报告候选的 max_weight 分布
阶段 4 之后可行集非空, 且网格搜索能返回解
投影后的权重既满足约束, 又不再退化为 one-hot
```

### R5 · 阶段 0 的 hash 要覆盖代码版本，不只是配置值

**位置**：计划 §2（阶段 0）交付物

**问题**：计划提出的交付物为：

```text
effective_research_protocol.json
candidate_config_manifest.json
evaluation_protocol_hash
```

这三项覆盖了**配置值**，但没覆盖**代码本身**。

```text
同一份配置 + 不同代码 = 不同行为
```

**建议**：`evaluation_protocol_hash` 的输入应包含：

```text
config values                    (计划已有)
code_commit_sha                  (新增)
dependency_lock_hash             (新增: numpy/pandas/scipy 版本会改浮点结果)
runtime_determinism_flags        (新增: 线程数, CPU/GPU, BLAS 后端)
```

**具体理由**：

- `numpy` 的 BLAS 后端不同（MKL / OpenBLAS）会产生不同的浮点结果，足以让"相同配置"产出不同的 IC
- 多线程归约顺序不确定，会让回测结果在机器间不可复现
- 这些都会破坏 `replay_bound` 的可信度

**验收条件**：

```text
两次独立 replay 在同一 commit + 同一依赖锁 + 同一确定性标志下得到相同 protocol hash
protocol hash 变化时能定位到是配置变了还是代码变了
```

### R6 · 把标准化诊断提前到阶段 0.5

**位置**：计划 §6.1 第 4 项

**问题**：计划要求：

```text
对每个因子保存去极值前后和中性化前后的 IC 对照
```

这个要求是对的，但它被放在阶段 4。而它**本质上是纯诊断**（只读，不改变系统）。

**为什么应该更早**：如果那 7 个负 IC 是未去极值的厚尾造成的，那么：

```text
阶段 1 的统计判决       -> 建立在一个被污染的信号上
阶段 3 的目标函数改写   -> 基于错误的收益来源认知
阶段 4 的 IC^+ 改法设计 -> 需要重新设计
```

**建议**：新增 **阶段 0.5**（纯诊断，不修改系统）：

```text
对 8 个因子分别计算:
  1. 原始 IC
  2. MAD 去极值后 IC
  3. 去极值 + 行业中性化后 IC
  4. 去极值 + 行业 + 市值中性化后 IC
输出: IC 符号在四种处理下的一致率
```

**成本极低**（重算 IC），**信息量极大**——它直接决定阶段 4 的 `IC^+` 改法该怎么设计。

**验收条件**：

```text
能回答: 7 个负 IC 是稳定的负, 还是标准化方式造成的
能回答: 哪些因子的符号对预处理方式敏感 (这类因子应该被降权或剔除)
```

### R7 · 给当前 challenger 一个明确的了结

**位置**：计划 §9（阶段 7）

**问题**：计划 §9.3 正确指出：

```text
标签定义 / 特征标准化 / 权重学习公式 / 目标函数 / Walk-Forward 参数 / 稳定性门禁 / 回测执行口径
任一变化 -> 旧 D1/D3/D5 证据失效
```

那么当前 challenger（`challenger_ready`，D2 = `review_required`）在阶段 7 之后将是一个**签名完全不同的候选**。

**风险**：它会长期停留在 `challenger_ready` 状态，造成"有一个候选在等着晋级"的假象。

**建议**：

```text
1. 在阶段 0 结束时, 把当前 challenger 归档为一个编号样本
2. 记录其完整签名和 D2 失败原因 (max_weight=0.7625 / q_noninferior=0.50 / filter=0.4286)
3. 状态明确置为 superseded, 而不是保留在 challenger_ready
4. 它作为"IC^+ 结构问题"的第一个实证样本保留在失败档案中
```

这符合计划核心原则 2（"保留前后对照和失败样本"）。

**验收条件**：

```text
当前 challenger 有明确的终态 (superseded), 不处于模糊状态
它的失败原因被固化为可引用的证据
新的 challenger 不会与它混淆
```

### R8 · 阶段 6 的消融要报告 J 的差值

**位置**：计划 §8（阶段 6）

**问题**：计划列出了六个消融变体：

```text
ATR + 时间退出
仅时间退出
仅 ATR
无主动退出
随机信号 + ATR
等权 baseline + ATR
```

这些变体的设计是对的。但如果只报告**收益率**，跨变体不可比——因为不同退出规则会产生不同的**交易次数、持有期、资金占用**，收益率之间没有可比性。

**建议**：每个变体报告：

```text
J 值 (与主目标一致的标量)
J 的各分项贡献
交易次数 / 平均持有期 / 换手率
```

**这样才能回答计划 §8 提出的验收问题**："能够回答高分来自信号还是退出规则"。

**关键对照**：

| 变体 | 目的 |
|---|---|
| 模型信号 + ATR + 时间退出 | 基准 |
| **随机信号 + ATR + 时间退出** | **若此变体的 J 接近基准 → J 的高分主要来自退出规则** |
| **等权 baseline + ATR + 时间退出** | 若此变体接近基准 → 权重学习没有贡献 |

**报告 ΔJ**：以"模型信号 + ATR + 时间退出"为基准，报告其余五个变体的 ΔJ。

**验收条件**：

```text
能定量回答 "gap 的 76% 权重贡献了多少 J"
能定量回答 "ATR 规则贡献了多少 J"
随机信号变体的 J 显著低于模型信号变体 (否则说明信号无效)
```

### R9 · `N_eff` 的最低门槛应由目标 Sharpe 反推

**位置**：计划 §3（阶段 1）判决建议

**问题**：计划提出：

```text
N_eff >= 预先定义的最低有效样本数
```

但"预先定义"的值没有给出，也没有给出推导依据。

**建议**：由目标 Sharpe 反推。所需 `N_eff` 满足：

```text
SR * sqrt(N_eff / 252) >= 1.96
=> N_eff >= (1.96 / SR)^2 * 252
```

再计入自相关导致的样本折损：

```text
N_eff = T / (1 + 2 * sum_k rho_k)
=> T >= N_eff * (1 + 2 * sum_k rho_k)
```

**核算结果**：

| 目标 Sharpe | 所需 `N_eff` | 日收益 ρ₁ | 所需 T | 折合年数 |
|---|---|---|---|---|
| 0.5 | 3872 | 0.0 | 3872 | 15.4 |
| 0.5 | 3872 | 0.2 | 5808 | 23.0 |
| **1.0** | **968** | **0.0** | **968** | **3.8** |
| **1.0** | **968** | **0.2** | **1452** | **5.8** |
| 1.0 | 968 | 0.4 | 2259 | 9.0 |
| 1.5 | 430 | 0.2 | 645 | 2.6 |

**含义**：

- A 股短线策略的日收益一阶自相关达到 0.2 是常见量级
- **若目标 Sharpe 为 1.0，最低门槛应设在约 1450 个交易日，而非计划当前的量级**
- `rho_k` 必须实测，不能假设

**建议写入阶段 1 的验收条件**：

```text
最低 N_eff 由目标 Sharpe 反推, 并写明反推过程
rho_k 由实测数据估计 (Newey-West 或 block bootstrap), 不假设为 0
若实测 rho_1 偏高导致所需 T 超出可用历史长度, 必须显式记录该约束,
而不是放低门槛
```

**补充说明**：这一条比阶段 5 的估计量选择更根本。**仪器的精度上限由样本量决定，换更好的估计量不能突破它。** 计划 §3 的验收条件"最短样本外长度由目标 Sharpe 和统计功效反推，而不是固定为 60 天"已经表达了正确方向——R9 只是把那句话变成可执行的公式。

## 5. 一句话总结

**计划的阶段顺序是对的**——先固定事实源、再建测量仪器的思路，比直接改 `gap` 权重正确得多。

**最该补强的两条**：

```text
R2  N_trials 必须包含历史上每一次回测, 否则 DSR 失真
R3  稳定性门禁的窗口数必须增加, 否则置信区间恒失败
```

**最容易被忽略的一条**：

```text
R6  标准化诊断应该在阶段 0.5 做, 而不是等阶段 4
    因为它决定了阶段 4 的改法该怎么设计
```

**原审查中需要由本项目持有人确认的一条**：当前 challenger 的集中（`gap = 0.7625`）已确认为 `IC^+` 结构 + 收缩公式的必然结果（近因）。但这 7 个负 IC 本身是否可靠，需要阶段 6 的置换检验回答。**在得到答案之前，不应把 `IC^+` 的改法当作纯粹的公式修补，也不应假定它一定有效。**
