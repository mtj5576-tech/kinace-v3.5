# Kinace V2.1 到 Kinace V3.2 的功能提升

## 总览

V2.1 已经提供研究数据库、交易级回测、滚动训练和人工晋升门禁。V3 的核心提升不是增加一个更大的回测脚本，而是修复数据、评分、回测和晋升之间的契约断链，并让系统在证据不足时自动停止。

| 能力 | Kinace V2.1 | Kinace V3 |
|---|---|---|
| 版本隔离 | V2.1 单版本运行 | 独立 `kinace-v3` 和 `kinace_v3` 包 |
| 数据库 | `D:\kinacesql\kinace_v2_1.sqlite3` | 独立 `D:\kinacesqlv3.2\kinace_v3_2.sqlite3` |
| V2.1 数据保护 | 同一数据库环境 | V2.1 只读不可变审计，禁止 V3 写入 |
| 数据门 | 无统一前置阻断 | 372 决策日、标签、原始输入、30 笔交易硬门禁 |
| 特征保存 | 主要保存 z-score 或部分 components | 保存原始特征、z-score、惩罚输入、标签和模型配置 |
| 候选验证 | 生成权重后仍评估旧推荐分数 | 使用候选配置重新计算 `score_replay` |
| 回测血缘 | 主要依赖 `model_version` 字符串 | candidate/replay/experiment/backtest 强 ID 和 SHA256 血缘 |
| 回测关联 | 晋升读取最新 completed 回测 | 回测必须属于指定候选和重放，存在歧义即拒绝 |
| 无未来函数 | 依赖现有实现约束 | 回测仅使用决策日前数据，下一交易日成交 |
| 实验记录 | 候选和窗口有限记录 | 记录代码版本、数据快照、搜索空间、种子和目标配置 |
| 自动调优 | 生成候选但流程仍可能继续评估旧分数 | 数据门失败时 `search_started=false` |
| 生产晋升 | 两阶段人工审批 | 当前完全关闭生产写入，只保留 dry-run 审计 |
| 可复现性 | 缺少统一 artifact hash | 快照、重放、实验和报告均内容寻址 |
| 交付边界 | 容易把流程可运行误认为结果有效 | 明确区分“契约通过”和“真实模型有效” |
| 数据采集 | 依赖当时抓取结果 | 内核保留采集与只读导入能力；V3.1 发布策略不启用历史回填 |
| 数据修订 | 以覆盖或当前状态为主 | append-only revision + supersede，不删除历史 |
| 开发数据门 | 无 30/60 日开发验证路径 | development gate 仅用于内部代码验证，不授权生产 |
| 正式数据门 | 依赖人工判断数据是否足够 | release gate 强制 372 日、标签、可交易状态和交易证据 |
| 交易状态数据 | 临时从行情或规则推导 | 正式 `security_state` 标准数据集 |
| 标签数据 | 外部评估文件为主 | 逐股票 `forward_labels` 标准数据集 |

## 1. 独立版本与数据库隔离

V3 使用独立目录、包名、配置、数据库和生产配置。它可以与 V2.1 同时存在，不需要迁移或覆盖 V2.1。

关键收益：

- V2.1 原命令和数据库继续可用。
- V3 实验不会污染 V2.1 推荐和回测数据。
- 默认路径和写入守卫降低串库风险。

## 2. 数据证据门

V2.1 能执行回测和训练命令，但现有数据库实际上只有 1 个独立决策日、0 条标签和 0 笔非零交易。流程能运行不代表数据足以训练。

V3 新增 stage-0 数据门，在搜索前检查：

- 独立决策日。
- 标注评估行。
- 原始特征、惩罚输入和模型配置。
- 可交易状态。
- 基线非零交易。

当前数据未通过硬门禁，所以搜索和训练正确停止。

## 3. 候选评分重放

V2.1 的 `train_walk_forward` 会拟合候选权重，但验证和测试阶段读取的是数据库中已存的 `i.score`。这会导致候选权重和验证结果之间断链。

V3 的 `score_replay` 使用：

```text
frozen raw inputs
+ candidate configuration
-> recalculated scores
-> canonical replay artifact
-> replay_id
```

同一输入和同一配置应产生相同结果；更换候选配置必须改变分数。

## 4. 候选专属回测

V2.1 回测从推荐快照读取旧分数，`model_version` 只是字符串筛选，不能证明回测属于某个候选模型。

V3 回测要求精确提供：

```text
candidate_id
replay_id
experiment_id
```

如果候选、重放和实验不匹配，或者一个重放对应多个实验，系统直接拒绝。回测不再使用“最新完成的回测”。

## 5. 实验和模型血缘

V3 新增实验注册层，记录：

- 代码版本。
- 数据快照哈希。
- 搜索空间。
- 随机种子。
- 目标配置。
- 候选、快照、重放和回测 ID。

这让每次研究结果可以追溯、复现和审计。

## 5.1 数据采集内部能力

V3.1 源码保留独立数据采集层，支持：

- CSV/JSON：不需要账号，适合历史文件回填和测试。
- Tushare Pro：通过 `TUSHARE_TOKEN` 获取真实市场数据。
- V2.1 Bootstrap：以只读方式利用已有 V2.1 数据库先完成 development gate。

V3.1 发布策略关闭历史回填和 provisional 生成。等待 Kinace V2.1 自然积累到至少
372 个有效独立决策日后，再通过后续明确批准的只读导入步骤接收完整数据。

## 6. Fail-closed 自动调优

数据门阻断时：

```text
search -> exit code 2
train  -> exit code 2
search_started=false
```

这与 V2.1 的主要差异是：V3 不会因为命令存在或样本很小就继续运行模型调优。

## 7. 生产安全

V3 当前没有生产审批路径：

- `model-promote` 必须使用 `--dry-run`。
- 不创建 `model.production.v3.json`。
- `production_changed=false`。
- `mutation_allowed=false`。

## 当前限制

V3 目前是研究内核，不是完整产品替换版。尚未包含：

- V2.1 完整 UI 的 V3 独立克隆。
- 真实历史 point-in-time 数据回填。
- 真实自动调优结果。
- V2.1 回测等价性结论。
- 生产模型发布。

这些能力必须等数据门通过并完成后续验证后再逐项解锁。
